# 🛡️ المرحلة 10: إدارة النسخ الاحتياطي واستعادة البيانات والملفات (Backups & Disaster Recovery)

> **الملف التعريفي الرئيسي للمرحلة العاشرة وفق معايير إطار عمل تقنية (Taqniya Framework v1.0).**

---

## 📌 1. نبذة عن المرحلة (Phase Overview)
- **اسم المرحلة:** إدارة النسخ الاحتياطي واستعادة البيانات والملفات (`phase_10_backups`).
- **الهدف العام:** تزويد الإدارة العليا للنظام بمحرك متكامل وآمن للنسخ الاحتياطي المفصول والمرن، يتيح خيارات:
  1. **نسخة كاملة (Full Backup):** تشمل قاعدة البيانات (MySQL) + كافة الملفات والمرفقات المرفوعة بالسيرفر.
  2. **قاعدة البيانات فقط (Database Only):** تفريغ فوري فائق السرعة وخفيف الوزن لجداول وبيانات النظام لضمان سلامة العمليات اليومية الحساسة.
  3. **الملفات فقط (Files Only):** حزم وأرشفة مجلد المرفقات والمستندات المرفوعة على القرص (`storage/uploads`).
- **الجهة المستفيدة والأدوار:** الإدارة العليا فقط (`role_type = 'admin'`).

## 🎯 2. نطاق المرحلة والمسارات المعمارية (Scope & Architecture)

### 📋 مصفوفة المسارات الستة (Master Endpoints):
| # | المسار | HTTP Method | الصلاحية | الغرض الوظيفي |
| :-: | :--- | :---: | :---: | :--- |
| **1** | `/api/v1/backups` | `GET` | `admin` | استعراض قائمة النسخ الاحتياطية وتصنيفها حسب النوع (`full`, `database`, `files`) مع إحصائيات الحجم والملاحظات. |
| **2** | `/api/v1/backups/create` | `POST` | `admin` | إنشاء وتوليد نسخة احتياطية فورية (كاملة أو قاعدة بيانات أو ملفات) مع ملاحظة اختيارية. |
| **3** | `/api/v1/backups/upload` | `POST` | `admin` | رفع واستيراد ملف نسخة احتياطية `.zip` مع التعرف التلقائي على نوع النسخة وتوجيهها للمجلد المخصص. |
| **4** | `/api/v1/backups/restore/:filename` | `POST` | `admin` | استعادة محتويات النسخة (جداول الـ SQL و/أو مجلد الملفات) مع حوكمة القيود واستبدال الملفات بأمان. |
| **5** | `/api/v1/backups/download/:filename` | `GET` | `admin` | تنزيل ملف النسخة الاحتياطية المضغوط إلى جهاز المستخدم. |
| **6** | `/api/v1/backups/:filename` | `DELETE` | `admin` | حذف ملف النسخة الاحتياطية نهائياً من مجلد التخزين المخصص بالسيرفر. |

## 📁 3. سياسة هيكلة مسارات تخزين الملفات (File Storage Structure Policy)
تعتمد المنظومة هيكلاً شجرياً منظماً يعزل ملفات كل وحدة وسجل لمنع تصادم الأسماء وتسهيل الأرشفة:
```text
storage/uploads/
├── assignments/{assignment_id}/      # مرفقات الواجبات المدرسية
├── quizzes/{quiz_id}/                # مرفقات الاختبارات القصيرة
├── official_exams/{exam_id}/          # مرفقات وجداول الامتحانات الرسمية
└── submissions/{submission_id}/      # تسليمات وإجابات الطلاب
```
- **في قاعدة البيانات:** يُخزن كائن المسار والبيانات الوصفية (`file_path`, `file_name`, `file_size`, `mime_type`) كمرجع نظيف وخفيف داخل حقول الـ JSON بدلاً من تشفير الملفات كنصوص ضخمة داخل الـ Database.

## 🔒 5. محددات الأمان والحوكمة (Security & Invariants)
1. **صلاحية حصرية للإدارة العليا (Admin-Only RBAC):** يُمنع المعلمون والطلاب وأولياء الأمور منعاً باتاً من الوصول لأي مسار نسخ احتياطي برفض فوري برمز `403 Forbidden`.
2. **عزل القيود المفتاحية أثناء الاستعادة:** تنفيذ استعلامات الاستعادة بداخل سياق محمي يبدأ بـ `SET FOREIGN_KEY_CHECKS=0;` وينتهي بإعادة التفعيل `SET FOREIGN_KEY_CHECKS=1;`.
3. **تفريغ دفعي للبيانات (Chunked Export):** تصدير الجداول الكبيرة عبر دفعات متتالية (500 سجل) لمنع استهلاك الذاكرة العشوائية للسيرفر.
4. **استعادة الملفات الذرية (Atomic Extraction):** فك الضغط أولاً في مجلد مؤقت `storage/restore_temp` ثم النقل لـ `storage/uploads` بعد التحقق من سلامة الأرشيف.
5. **تسجيل وتوثيق العمليات (Audit Logging):** توثيق كل عملية إنشاء، استعادة، رفع، أو حذف في سجل العمليات الإدارية لضمان المساءلة والحماية.
